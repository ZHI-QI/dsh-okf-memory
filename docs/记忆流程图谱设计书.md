# dsh-okf-memory 记忆流程图谱 — 设计书

> 版本:V1(评审稿) · 日期:2026-08-31
> 目标:给 dsh-okf-memory 新增「**记忆流程可视化图谱**」,作为差异化卖点,提升下载量与传播力。
> 定位澄清:这不是 dsh-okf 的**静态论文知识图谱**,而是可视化 dsh-okf-memory **自己的记忆学习过程**。

---

## 1. 背景与动机

- dsh-okf-memory 的卖点是"神经自我学习"——预测性唤起、不确定性驱动捕获、强化反馈、巩固与遗忘。
- 但这些能力目前**藏在后端**,用户看不到;截图里 dsh-okf 的酷炫知识图谱提供了"可传播的视觉锚点"。
- 需求:**把 dsh-okf-memory 的记忆循环可视化**,让用户一眼看到"插件在怎么学、记忆怎么流转、哪些被强化/衰减"。
- 结论:图谱是**为下载量服务的传播载体**,神经记忆是真正的底座,两者结合。

## 2. 差异化定位(为什么不和 dsh-okf 撞脸)

| | dsh-okf | dsh-okf-memory 本设计 |
|---|---|---|
| 图谱对象 | 科研论文→概念(静态知识网) | **记忆生命周期**(动态学习过程) |
| 节点语义 | Paper/Topic/Method/Entity… | **记忆概念**(Fact/Preference/Decision/Method/Insight/Idea/Lesson/TechChoice) |
| 边语义 | 论文引用/主题关联 | **交叉链接(related)+ 权重流向** |
| 视觉焦点 | 知识聚类 | **记忆流转/学习信号/权重演化** |

一句话:**dsh-okf 给你"世界长什么样",我们给你"你的 AI 怎么在记"**。

## 3. 三大视图规格

### 视图 ① 记忆图谱 Memory Graph(核心)
- **节点**:每个记忆概念一个节点
  - 大小 = 权重(active 权重高 → 大)
  - 颜色 = type(8 类配色)
  - 形状/描边 = 状态(active 实心 / archived 描边虚线)
  - 悬停 = 显示 title/description/权重/最近访问
- **边**:概念间的 `related` 交叉链接(无向、可加粗细表示关联强度)
- **布局**:力导向(Fruchterman-Reingold / D3-force),节点越多越收紧,支持缩放拖拽
- **筛选器**:按 type / 标签 / 状态(active|archived) 过滤;关键词高亮
- **点击节点** → 跳到 `okf_read` 详情(正文 + 交叉链接)

### 视图 ② 记忆流 Memory Flow(记忆四阶段)
- 展示 **捕获 → 概念化 → 沉淀 → 唤起** 的流转(桑基图 or 横向管道 + 动画)
- 每阶段显示计数(本库共捕获 N 次、概念化 M 篇、沉淀 K 篇、唤起 L 次),数据来自 `log.md` 与 weights
- 可选:时间倒放(把"一段会话如何被沉淀"演出来)—— 强传播性,适合做宣传动画/GIF

### 视图 ③ 学习热力 Learning Heatmap(强化反馈)
- **权重时间线**:每条记忆的权重随 `recordSelect/recordSkip/consolidate` 的曲线(上升/衰减/归档/复活)
- **TechChoice 演化**:某维度候选表 v1→vN 的迭代轨迹(哪个候选被拍板、旧候选如何降级)—— 直接呼应"三档规则"
- **热力矩阵**:type × 时间 的活跃度(哪些类型近期被用得最多)

## 5. 技术路径与里程碑

| 里程碑 | 内容 | 依赖 |
|---|---|---|
| **M1 数据层** | `okf_graph` 工具 + `graph.json` 服务(输出 nodes/edges/learning),复用 `scanBundle`+`parseFrontmatter`+`learning.weights` | 低,现有数据即可 |
| **M2 前端图谱** | client-plugin 面板 + 记忆图谱视图(node/edge/筛选/缩放) | 中,需先调研 DSH client-plugin 精确 API |
| **M3 学习可视化** | 记忆流动画 + 权重热力时间线 + TechChoice 演化 | 高,动画/布局打磨 |

**依赖/前置风险(写书时已查证)**:
- DSH 源码解包目录里未直接搜到 cliente-plugin 痕迹 → **M2 开工前必须先专项调研** `dsh web` 的 client 面板注入机制(参考 dsh-okf 的 Web UI 实现,它已成功落地该形态)。
- 前端库:d3-force(或 @antv/g6)布局;需确认能接入 DSH 的 client 运行时。

## 6. 数据来源映射(现有 lib 已具备)

| 图谱数据 | 来源 |
|---|---|
| 节点(title/type/tags/description) | `scanBundle` + `parseFrontmatter` |
| 节点状态/权重 | `learning.loadMeta().entries` |
| 边(交叉链接) | `recall()` 提取的 `links`,写入时 `related` 互链 |
| 权重历史/TechChoice 演化 | `.meta/weights.json` + `log.md` 时间线 |

## 7. 验收标准

- [ ] `okf_graph` 输出合法 `graph.json`,与真实记忆库(dsh-okf-memory 插件库)一致
- [ ] 前端渲染出可缩放/筛选的实体节点+关系边图谱
- [ ] 记忆流三阶段计数正确
- [ ] 权重热力时间线/TechChoice 演化图正确
- [ ] 全程不污染真实记忆库;`npm test` 5 套件全绿
- [ ] 图谱作为 feature 分支开发,不直推 main(遵守既定 Idea)

## 8. 不做的事(边界)

- 不做 dsh-okf 那套科研 PDF 收录/综述写作(那是另一个插件,避免重复造轮子)
- 不做多用户/云端同步(记忆库是单机 `~/.dsh/memory`)
- 不做全文语义检索重排(已有 `okf_search`/可后续接 dsh-okf)
